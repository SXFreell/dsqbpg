# 戴森球蓝图生成器 — 实施计划

## 目标

构建一个 Web 应用，允许用户：
1. 选择目标产物 + 指定目标产量
2. 自动计算所需生产设备（建筑数量、原料需求）
3. 自动生成戴森球蓝图（可导入游戏的蓝图字符串）

## 技术栈

- **运行时**: Bun（服务端 + 打包器）
- **前端框架**: React 19 + react-router-dom v7
- **UI**: Tailwind CSS 3 + shadcn/ui（Radix 组件库）
- **语言**: TypeScript
- **参考项目**: refs/dsp-calc（量化计算器）、refs/edit-dspblue-print（蓝图编辑工具）

## 系统架构

```
用户输入（产物 + 目标产量）
    │
    ▼
┌─────────────────┐
│   量化计算引擎    │  ← 移植自 dsp-calc（线性规划求解）
│  src/lib/calc/   │
└────────┬────────┘
    │ 设备清单 {建筑类型, 数量}
    ▼
┌─────────────────┐
│   布局引擎       │  ← 新增：v1 线性排列
│  src/lib/layout/ │
└────────┬────────┘
    │ 带坐标的建筑列表
    ▼
┌─────────────────┐
│   蓝图编码器     │  ← 基于 edit-dspblue-print 格式
│ src/lib/blueprint│
└────────┬────────┘
    │ DSP 蓝图字符串
    ▼
┌─────────────────┐
│   UI 层（React）  │  复用现有 shadcn/ui 组件
│  src/pages/      │  Calculator → Blueprint → Export
└─────────────────┘
```

## 模块划分

### 阶段一：游戏数据层 `src/lib/dsp/`

| 文件 | 来源 | 内容 |
|------|------|------|
| `types.ts` | 新建 | `Item`, `Recipe`, `Building` 等 TS 接口 |
| `items.ts` | 移植 | 所有物品常量 |
| `recipes.ts` | 移植 | 所有配方（标准 / 增产剂 / 稀有矿物替代） |
| `buildings.ts` | 移植 | 建筑属性（占地尺寸、速度倍率） |
| `belts.ts` | 移植 | 传送带等级、速度参数 |
| `index.ts` | 新建 | 统一导出 |

### 阶段二：量化计算引擎 `src/lib/calc/`

| 文件 | 来源 | 内容 |
|------|------|------|
| `types.ts` | 新建 | `CalcInput`, `CalcOutput`, `CalcNode` |
| `solver.ts` | 移植 | 线性规划求解器 |
| `chain.ts` | 提取 | 配方链展开 |
| `ores.ts` | 提取 | 矿脉消耗计算 |
| `index.ts` | 新建 | 统一导出 |

**核心算法流程**：
1. 用户指定目标产物 + 目标产量（items/min）
2. 沿配方树向上回溯到矿脉
3. 构建线性规划矩阵（变量=中间产物产量，约束=配方比例+建筑速度）
4. 求解得出每级产物所需设备+矿脉需求

### 阶段三：蓝图引擎 `src/lib/blueprint/`

| 文件 | 来源 | 内容 |
|------|------|------|
| `types.ts` | 新建 | `BlueprintData`, `PlacedBuilding`, `BeltSegment` |
| `encoder.ts` | 移植 | 编码为 DSP 可导入的字符串 |
| `decoder.ts` | 移植 | 解析已有蓝图 |
| `hash.ts` | 移植 | 蓝图完整性校验 hash |
| `index.ts` | 新建 | 统一导出 |

### 阶段四：布局引擎 `src/lib/layout/`（v1 线性排列）

| 文件 | 内容 |
|------|------|
| `types.ts` | 位置、边界盒等类型 |
| `grid.ts` | 网格坐标系统 |
| `planner.ts` | 线性布局规划器（MVP 核心） |
| `belt-router.ts` | 传送带直连（v1 简化版） |
| `sorter-connect.ts` | 分拣器自动连接 |
| `index.ts` | 统一导出 |

**v1 布局策略**：按生产链顺序从左到右线性排列：
矿脉 → 熔炉 → 一级制造 → 二级制造 → ... → 最终产物

### 阶段五：UI 层改造

**改造页面**：
- Calculator `/calculator`：产物选择器 + 产量输入 + 计算结果展示
- Blueprints `/blueprints`：蓝图预览 + 导出

**新增组件**：
- `ProductPicker.tsx`：按分类筛选的产物选择器
- `CalcResultTable.tsx`：设备计算结果表格
- `BlueprintCanvas.tsx`：2D 蓝图预览（Canvas）

## 各阶段 QA 验证方案

### 阶段一（数据层）QA
| 工具 | 操作 | 预期结果 |
|------|------|---------|
| `bun run tsc --noEmit` | 对整个 `src/lib/dsp/` 做类型检查 | 零类型错误，所有导出的 Item/Recipe/Building ID 均可索引 |
| 单元测试 | 验证所有物品 ID 唯一，每个配方引用的输入/输出物品 ID 在物品表中存在 | 无悬垂引用 |

## MVP 实施顺序

| 优先级 | 阶段 | 预估 |
|--------|------|------|
| P0 | 阶段一：游戏数据层 | 数据搬运为主 |
| P0 | 阶段二：计算引擎 | 移植+适配 |
| P1 | 阶段五：计算器 UI | 端到端可验证 |
| P1 | 阶段三：蓝图编码 | 打通输出链路 |
| P2 | 阶段四：v1 线性布局 | 新增核心模块 |
| P2 | 阶段五：蓝图预览 UI | 完整交互闭环 |

## 关键风险

| 风险 | 缓解 |
|------|------|
| 增产剂/稀有替代分支使线性规划变量爆炸 | 先做标准配方，逐步加分支 |
| 布局算法（矩形装箱 NP-hard） | v1 用线性排列，足够 MVP |
| 传送带路径规划（A*寻路+防交叉） | v1 只做直连 |
| 蓝图格式随游戏版本变化 | 单独模块封装格式解析逻辑 |
